## 1. 引言

### 1.1 编写目的

本文档定义 CEATS 系统的功能需求、非功能需求与外部接口需求，作为后续设计、编码与测试的唯一依据。
所有需求均给出**可验证标准**，避免出现「提升成绩」这类无法度量、无法验收的表述。

### 1.2 项目背景

面向公务员考试（行政职业能力测验）备考者在真实备考中遇到的三个痛点：

1. **信息获取难**：招考公告分散在多个官网，格式不统一，容易错过报名与资格审核节点；
2. **进度难量化**：刷题量很大，但缺乏「近期是进步还是退步」的客观依据；
3. **弱项不明确**：直觉上知道某个模块弱，但无法定位到具体考点，也无法区分是「不会做」还是「做得慢」。

### 1.3 术语定义

| 术语 | 说明 |
| --- | --- |
| 模块 | 行测五大模块：言语理解与表达、判断推理、数量关系、资料分析、常识判断 |
| 考点 | 模块下的细分知识点，例如资料分析 → 隔年增长率 |
| 单题耗时 | 一次练习的总用时 ÷ 总题数（秒） |
| 弱项 | 综合得分低于 60 分的模块 |
| 正确率 | 对题数 ÷ 总题数 |

## 2. 总体描述

### 2.1 系统目标

以「轻界面、重逻辑、数据驱动」为设计原则，构建一个**本地运行、数据不外传**的备考量化分析工具：
公告自动追踪、练题数据沉淀、弱项科学诊断、知识速查、备考计划拆解、闪卡自测、错题复盘与报告留存。

### 2.2 用户角色

| 角色 | 特征 | 核心诉求 |
| --- | --- | --- |
| 备考考生（主要用户） | 个人备考者，非技术用户 | 快速录入成绩、查看公告、看懂弱项结论 |
| 系统管理员（开发/维护者） | 项目开发者本人 | 维护监控站点列表、维护本地数据库、清理冗余数据 |
| 招考官方网站（外部系统） | 人社局、国家公务员局等 | 提供公开的公告列表页（本项目只读） |
| 本地数据库（内部组件） | SQLite 单文件数据库 | 持久化练习记录与公告，供分析模块查询 |

### 2.3 运行环境

- 操作系统：Windows 11（兼容 macOS / Linux）
- 运行环境：Python 3.10+（开发环境为 3.12.4）
- 界面形式：命令行（CLI），无图形界面依赖
- 数据存储：SQLite 3 本地文件 `data/ceats.db`

### 2.4 假设与约束

- 假设用户具备基础命令行操作能力；
- 约束：单用户、单机使用，不做多用户并发与权限体系设计；
- 约束：首期仅监控国家公务员局与广东省人事考试局两个站点，控制抓取范围。

## 3. 功能需求

| 模块 | 需求编号 | 需求内容 | 可验证标准 |
| --- | --- | --- | --- |
| 公告聚合 | FR-INF-01 | 系统需自动抓取并显示国考/省考官网的最新公告标题 | 运行 `scrape` 命令后，能列出抓取到的公告标题与链接；实测广东省人事考试局返回 30 条 |
| 公告聚合 | FR-INF-02 | 支持按关键词标记与检索公告 | `--keywords 报名,公告` 参数生效；`matched_keyword` 字段被正确写入，可按关键词过滤 |
| 成绩录入 | FR-REC-01 | 支持录入日期、模块、考点、总题数、对题数、用时 | 提交后 `practice_records` 表中新增一条记录，且各字段值与输入一致（如 `25:30` → `duration_seconds = 1530`） |
| 成绩录入 | FR-REC-02 | 录入后立即计算并反馈正确率与单题平均耗时 | 输出形如「正确率 45.0%，单题耗时 76.5s（偏慢）」 |
| 成绩录入 | FR-REC-03 | 非法输入必须被拦截且不写入数据库 | 总题数输入 `abc`、对题数大于总题数时提示错误，且表中记录数不增加 |
| 能力分析 | FR-ANA-01 | 根据历史数据生成各模块正确率雷达图 | 执行 `chart` 后生成 `radar.png`，五个轴对应五大模块，弱项模块被标红 |
| 效率分析 | FR-ANA-02 | 计算单题平均耗时并标注异常值 | 单题耗时超过 60 秒的模块出现在「效率预警」列表中 |
| 弱项诊断 | FR-ANA-03 | 输出模块综合得分排名与薄弱考点 | 报告按综合得分升序列出模块，并列出正确率低于 60% 的具体考点 |
| 趋势分析 | FR-ANA-04 | 按日展示正确率与单题耗时走势 | 生成 `trend.png`，横轴为日期且按时间升序 |
| 知识库 | FR-KB-01 | 支持通过关键词查询行测公式与申论模板 | 输入「隔年增长率」返回 `R = r1 + r2 + r1×r2` 及其示例 |
| 数据管理 | FR-DATA-01 | 支持初始化数据库与字典数据，且不破坏已有记录 | 重复执行 `init` 后练习记录数不变 |
| 数据管理 | FR-DATA-02 | 支持设置备考目标（考试名称、日期、目标分数） | 设置后可查询到该目标，重复设置同名称考试时覆盖更新 |
| 备考计划 | FR-PLAN-01 | 支持录入考试日期，并在每次系统启动时自动提醒距考试剩余天数 | 设置 `--date 2027-11-28` 后，任意子命令启动时输出「[倒计时] 距离 2027 年国家公务员考试 还有 433 天」；未设置时只提示如何设置，任何命令都不得写入默认计划 |
| 备考计划 | FR-PLAN-02 | 输入目标岗位总分后，按公考黄金比例自动拆解各模块建议目标正确率 | 目标 135 分时输出言语 75%、判断 75%、资料 85%、数量 60%、常识 55%；目标分变化时等比例缩放并钳制在 30%~95% |
| 备考计划 | FR-PLAN-03 | 各模块建议目标需与当前正确率比对，给出差距结论 | 表格「差距」列输出「差 15.3 个百分点」或「已达标（+3.0%）」；无数据时输出「暂无数据」 |
| 闪卡抽测 | FR-QUIZ-01 | 不依赖大模型，从知识库随机抽取知识卡片要求用户作答 | 执行 `quiz --count 5` 后随机抽取 5 条不重复卡片，题面隐藏标准答案 |
| 闪卡抽测 | FR-QUIZ-02 | 自动判分并给出得分、等级与遗漏要点 | 完全作答记 100 分「完全正确」；`R = r1 + r2 + r1xr2` 记 66.7 分「基本正确」；未作答记 0 分 |
| 闪卡抽测 | FR-QUIZ-03 | 抽测结果入库，可查看历史掌握情况 | `quiz --stats` 输出累计作答次数、通过率、平均得分与最弱知识点 |
| 错题备忘 | FR-NOTE-01 | 录入成绩时可标记错题/难题，也可事后补打或取消标记 | `record --wrong` 写入 `is_wrong = 1`；`note --id 3 --clear` 可取消；`list --wrong` 只列出错题记录 |
| 错题备忘 | FR-NOTE-02 | 自动挑选最近做错最多、单题耗时最长的 3 个考点生成复盘清单 | `review` 输出按优先级排序的最多 3 条考点，含错题数、正确率、耗时与入选原因；仅"有错题 / 正确率 < 60% / 单题耗时 > 45 秒"的考点可入选，全部正常时说明"均未触发复盘条件" |
| 报告导出 | FR-EXP-01 | 支持一键导出 Markdown / CSV 诊断报告 | `export --format all` 生成 `2026-国考备考诊断报告.md`（8 个章节）与 `ceats-练习记录-YYYY-MM-DD.csv`（UTF-8 BOM） |
| 报告导出 | FR-EXP-02 | 支持一键备份数据库为带时间戳的文件 | `backup` 生成 `ceats_20260921_225734.db`，使用 SQLite `Connection.backup` 保证快照一致性；`backup --list` 可枚举；同一秒内重复备份自动追加 `_1` 序号，不得互相覆盖；数据库不存在或无练习记录时拒绝备份并返回非零码 |
| 报告导出 | FR-EXP-03 | 支持从备份安全还原，且校验失败不得破坏现有数据 | `restore` 校验文件头与核心表；校验失败时目标库记录数不变；还原前自动对当前库再备份一次 |

## 4. 非功能需求

| 类型 | 需求编号 | 需求内容 | 可验证标准 |
| --- | --- | --- | --- |
| 性能 | NFR-PERF-01 | 本地数据库查询响应时间 < 0.5 秒 | 在 120 条记录（1755 题）规模下，聚合查询实测在 0.01 秒量级 |
| 易用性 | NFR-USAB-01 | 提供简洁的命令行引导流程 | 交互模式下有明确的分步提示；单次录入实测约 20 秒（要求 ≤ 30 秒） |
| 安全性 | NFR-SEC-01 | 数据库文件存放在本地，不上传敏感成绩 | 数据库为项目根目录下 `data/ceats.db`；程序中不存在任何数据上报逻辑 |
| 稳定性 | NFR-STAB-01 | 爬虫遇到网络断开或页面改版时需有友好提示，不得崩溃 | 断网时输出「网络连接失败」等提示并降级为官方链接导航；单站点失败不影响其他站点 |
| 可靠性 | NFR-REL-01 | 数据库约束必须防止脏数据 | 外键约束、`CHECK` 约束（对题数 ≤ 总题数、题数 > 0）均生效，非法写入抛出 `IntegrityError` |
| 可维护性 | NFR-MAIN-01 | 业务参数集中配置，修改口径无需改动业务代码 | 目标单题耗时、异常阈值、弱项阈值、评分权重均在 `src/config.py` |
| 可测试性 | NFR-TEST-01 | 测试不依赖真实网络与真实数据文件 | 323 个用例全部通过（单元 313 + 集成 10），语句覆盖率 91%（新模块 planner / quiz / exporter 均为 100%） |
| 可靠性 | NFR-REL-02 | 启动提醒与备份还原等附加功能不得阻断主流程 | 数据库缺失或读取异常时倒计时提醒静默跳过；还原失败时目标库保持原状 |

## 5. 外部接口需求

### 5.1 用户接口

- 命令行子命令：`init` / `record` / `list` / `report` / `chart` / `plan` / `quiz` / `review` / `note` / `export` / `backup` / `restore` / `scrape` / `kb` / `demo` / `menu`
- 交互菜单：12 个功能入口 + 退出，非法编号只提示不退出，`Ctrl+C` 只取消当前操作
- 启动提醒：进入交互菜单或执行任意子命令（`init` 除外）时，若已设置备考计划则先打印一行倒计时摘要

### 5.2 外部站点接口

| 站点 | 地址 | 用途 |
| --- | --- | --- |
| 国家公务员局 | http://www.scs.gov.cn/ | 国考公告列表 |
| 广东省人事考试局 | https://rsks.gd.gov.cn/ | 省考及专业技术资格考试公告 |
| 中国人事考试网 | http://www.cpta.com.cn/ | 降级导航备用入口 |
| 广东省人力资源和社会保障厅 | https://hrss.gd.gov.cn/ | 降级导航备用入口 |

抓取约定：统一 UA、8 秒超时、最多重试 2 次、递增退避；仅解析 `<a>` 标签的标题与链接，不抓取正文。

### 5.3 数据接口

- SQLite 连接：`sqlite3.connect(data/ceats.db)`，开启 `PRAGMA foreign_keys = ON`
- 数据目录可通过环境变量 `CEATS_DATA_DIR` 重定向（便于自动化测试）

## 6. 数据库设计

### 6.1 表结构

| 表名 | 字段 | 约束 |
| --- | --- | --- |
| `modules` | id, code, name, weight | PK id；UK code、UK name；weight ∈ [0,1] |
| `topics` | id, module_id, name, difficulty | PK id；FK module_id → modules(id) ON DELETE CASCADE；UK (module_id, name) |
| `practice_records` | id, record_date, module_id, topic_id, total_questions, correct_questions, duration_seconds, note, is_wrong, created_at | PK id；FK module_id / topic_id；CHECK 题数为正、对题数 ≤ 总题数、用时 > 0、is_wrong ∈ {0,1} |
| `announcements` | id, source, title, url, publish_date, matched_keyword, fetched_at | PK id；UK url（实现抓取去重） |
| `knowledge_items` | id, keyword, category, content, example | PK id；UK keyword；category ∈ {公式, 解题技巧, 申论模板} |
| `exam_plans` | id, exam_name, exam_date, target_score, essay_score, created_at | PK id；UK exam_name；essay_score ∈ [0,100] |
| `quiz_log` | id, quiz_date, keyword, category, user_answer, score, passed, elapsed_seconds, created_at | PK id；CHECK score ∈ [0,100]、passed ∈ {0,1} |

> 旧版本数据库通过 `MIGRATION_STATEMENTS` + `PRAGMA table_info` 探测后增量 `ALTER TABLE`
> 补列（`is_wrong`、`essay_score`）并新建 `quiz_log`，不丢失已有成绩数据。

### 6.2 索引设计

| 索引 | 列 | 优化场景 |
| --- | --- | --- |
| `idx_record_date` | practice_records(record_date) | 按日期区间统计趋势 |
| `idx_record_module` | practice_records(module_id, record_date) | 模块 + 时间联合过滤（雷达图） |
| `idx_record_topic` | practice_records(topic_id) | 考点粒度下钻 |
| `idx_ann_fetched` | announcements(fetched_at) | 公告按抓取时间排序 |
| `idx_quiz_date` | quiz_log(quiz_date) | 闪卡抽测按日期统计

### 6.3 设计说明（第三范式）

统计指标（正确率、单题耗时、综合得分）**一律不入库**，全部由业务层实时计算，
从根本上避免派生数据与原始数据不一致；模块名、考点名只存在于字典表，
事实表通过外键引用，不存在传递依赖。
